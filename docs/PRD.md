## 과제 개요

문서를 업로드하면 내용을 분석하고, 사용자 질문에 대해 **문서 근거 기반 답변**을 생성하는 REST API 서버를 구현하세요.

**완성도보다 설계 의도와 구현 품질을 우선 평가합니다.** 부분 구현도 평가 대상이며, 미구현 부분은 설계 문서로 대체할 수 있습니다. 다만 §불합격 기준에 해당하는 항목은 예외입니다.

## 🚀 과제 시작 — `serithemage` Collaborator 초대

**과제의 시작은 코딩이 아니라 초대입니다.**

1. 이 리포지토리 → "Use this template" → 본인 계정 **Private** 리포 생성
2. **[`serithemage`](https://github.com/serithemage)를 Collaborator로 초대** ← **첫 커밋 전에 보낼 것**
3. `git config core.hooksPath .githooks` (Retrobot 활성화) 후 구현 시작

Private 리포이므로 초대 전에는 평가자가 리포의 존재도, 착수 시점도 확인할 수 없습니다. **초대 없이 제출된 과제는 평가 대상이 아닙니다.** 또한 아래 168시간 창은 첫 커밋부터 세므로, 초대를 먼저 보내두면 착수 시점이 실시간으로 기록되어 사후 분쟁이 생기지 않습니다.

초대가 첫 커밋보다 늦었다는 사실만으로는 불이익이 없습니다. 다만 확인 절차가 번거로워지므로 리포 생성 직후에 보내주세요.

## ⏱ 작업 시간 규칙 — 168시간 창 (이번 라운드 신설)

**착수 시점은 자유이되, 첫 커밋으로부터 168시간(=24h × 7일) 이내의 커밋만 평가 대상입니다.**

| 항목 | 정의 |
|------|------|
| **시작 신고** | `serithemage` Collaborator 초대 (§과제 시작) — 첫 커밋 전 권장 |
| **T0 (창 시작)** | 지원자 리포의 **첫 커밋** 시각. 단, "Use this template"으로 생성된 최초 커밋(템플릿과 내용이 동일한 커밋)은 제외하고, **지원자가 작성한 첫 커밋**을 T0로 봅니다 |
| **창 종료** | `T0 + 168시간` |
| **하드 컷** | **2026-08-09 (일) 23:59 KST**. `T0 + 168h`가 이 시각을 넘으면 하드 컷에서 잘립니다 → 창을 온전히 쓰려면 **늦어도 2026-08-02 23:59 KST에는 시작**해야 합니다 |
| **창 밖 커밋** | 제출 무효는 아니지만 **채점에서 제외**됩니다. 평가자는 창 안 마지막 커밋을 체크아웃한 상태로 실행·채점합니다 |
| **판정 기준** | `git log`의 **committer date**. GitHub push 이벤트 기록과 교차 확인합니다 |

**예외는 없습니다.** README 정리·오탈자 수정도 창이 닫힌 뒤의 커밋이면 채점 대상이 아닙니다. 마무리 작업까지 168시간 안에 포함해 계획하세요.

> **왜 이런 규칙인가**: 이전 라운드는 "7일"이 달력 기준이라 실제 투입 시간 편차를 통제할 수 없었습니다. 168시간 창은 **바쁜 지원자가 원하는 주에 시작할 수 있게 하면서도 모두에게 동일한 작업 시간을 보장**하기 위한 장치입니다. 창을 다 쓰지 않아도 됩니다 — 3일 만에 제출해도 감점 없습니다.

## 핵심 요구사항

### 1. 문서 수집 (Ingestion)

- 문서 파일(PDF, TXT 등)을 업로드하면 텍스트를 추출하고, 검색 가능한 형태로 저장한다.
- 최소 2개 이상의 파일 포맷을 지원한다.

### 2. 질의응답 (Query & Answer)

- 사용자 질문에 대해 업로드된 문서에서 관련 내용을 검색(RAG)하고, LLM을 호출하여 답변을 생성한다.
- 답변에는 **출처(어떤 문서의 어떤 부분에서 왔는지)** 가 포함되어야 한다.
- 문서에 근거가 없는 질문에 대해서는 환각 없이 적절히 처리해야 한다.
- **스트리밍 응답을 지원한다** (SSE 등). 답변 전체를 수집한 뒤 한 번에 반환하는 방식만 있으면 감점입니다. 비스트리밍 엔드포인트를 함께 두는 것은 자유입니다.

### 3. LLM 응답 캐싱

- 동일하거나 **유사한** 질문에 대해 LLM을 재호출하지 않도록 **캐시 DB**를 활용한다.
- 캐시 히트 여부를 응답에서 확인할 수 있어야 한다.
- **문서가 변경되면 관련 캐시가 무효화되어야 한다.**

### 4. 프롬프트 설계

- RAG 파이프라인에 사용되는 프롬프트를 직접 설계한다.
- 프롬프트 설계 의도와 전략을 설명하는 문서(`PROMPT_DESIGN.md`)를 작성한다.

### 5. 자동화 테스트 (이번 라운드 신설)

핵심 경로에 대한 **실행 가능한 자동화 테스트**를 작성한다. 최소 다음 3개 경로를 덮어야 합니다:

| 경로 | 확인할 것 |
|------|----------|
| **Ingestion** | 파일 업로드 → 텍스트 추출 → 저장까지 성공하는가 |
| **Retrieval** | 질의에 대해 기대한 청크/문서가 상위에 검색되는가 |
| **캐시 무효화** | 문서 변경 후 관련 캐시가 실제로 무효화되는가 |

- 테스트 실행 방법을 `README.md`에 한 줄 명령으로 명시한다 (예: `pytest`, `docker compose run --rm api pytest`).
- LLM 호출은 목(mock)/스텁으로 대체해도 됩니다. **테스트가 LLM 구독 없이 돌아가면 가산점**입니다.
- 커버리지 수치는 평가하지 않습니다. **무엇을 왜 테스트했는지**를 봅니다.

## 기술 조건

| 항목 | 조건 |
|------|------|
| 언어 | Python 3.11+ |
| 프레임워크 | FastAPI |
| LLM / 에이전트 | 아래 SDK 중 택 1 (별도 API 키 불필요, 구독 기반 이용) |
| 실행 | `docker compose up` 또는 README에 명시된 방법으로 **한 줄 실행** 가능 |
| 테스트 | README에 명시된 방법으로 **한 줄 실행** 가능 |

### LLM 연동 방식

별도의 API 키 발급 없이, **구독 기반으로 이용 가능한 SDK**를 사용합니다.

| SDK | 설치 | 비고 |
|-----|------|------|
| **Claude Code SDK** (`claude-code-sdk`) | `pip install claude-code-sdk` | Anthropic Claude 모델 사용. Claude Pro/Max 구독으로 이용 |
| **Codex CLI** (`@openai/codex`) | `npm install -g @openai/codex` | OpenAI 모델 사용. ChatGPT Pro 구독으로 이용 |

- 두 SDK 모두 로컬 CLI 도구를 프로그래밍 방식으로 호출하는 형태입니다.
- 어떤 SDK를 선택했는지, 서버 코드에서 어떻게 통합했는지를 `ARCHITECTURE.md`에 설명해주세요.
- 임베딩 모델은 선택한 SDK 또는 오픈소스 임베딩 모델(sentence-transformers 등)을 자유롭게 활용하세요.

벡터 DB, 캐시 DB, 청킹 전략, 검색 방식 등 **그 외 기술 선택은 지원자의 판단에 맡깁니다.**
선택의 이유를 `README.md` 또는 `ARCHITECTURE.md`에 간략히 설명해주세요.

### 문서-코드 일치 (이번 라운드 명문화)

`ARCHITECTURE.md`·`README.md`에 적은 내용과 실제 구현이 **일치해야 합니다.** 이전 라운드에서 "문서에는 FAISS인데 구현은 Chroma", "문서 단위 표기와 코드 단위 불일치" 같은 사례가 반복됐습니다.

- 불일치는 **감점 요인**입니다 (Track A 각 영역에서 차감).
- 도중에 기술 선택을 바꿨다면 **문서를 고치거나**, 바꾼 이유를 문서에 남기세요. 후자가 오히려 가산점입니다.
- 미구현을 "구현했다"로 적은 경우는 감점이 아니라 §불합격 기준(허위 기재)에 해당합니다.

## 불합격 기준

- 명시된 방법으로 **실행 불가** (평가자가 `docker compose up` 등 README 절차를 1회 수행해 확인합니다)
- LLM/에이전트 SDK 호출 없이 하드코딩된 응답
- 벡터 검색 또는 캐시 DB 미구현
- **자동화 테스트 전무** (§5 — 3개 경로 중 하나도 없는 경우)
- 기존 오픈소스 프로젝트 통째로 복사
- 문서에 구현했다고 적었으나 해당 코드가 존재하지 않는 경우 (허위 기재)
- 168시간 창 안에 유의미한 산출물이 없고, 창 밖 커밋에만 구현이 존재하는 경우
